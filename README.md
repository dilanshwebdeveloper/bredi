# B.R. Edible Oils ERP

Flutter application starter for B.R. Edible Oils Pvt. Ltd. covering factory operations, inventory, sales, finance, staff, and reporting.

## Run locally

1. Install Flutter (Dart SDK `>=3.3.0 <4.0.0`).
2. Run `flutter pub get` and `flutter run`.
3. The dashboard can be previewed without Firebase in demonstration mode. To enable authentication and cloud data, create a Firebase project, enable Email/Password Authentication and Cloud Firestore, then run `flutterfire configure`. Ensure generated platform configuration is installed for Android, Windows, and Web before enabling production use.
4. Firebase Android application ID supplied for setup: `1:893650543343:android:8a6834e5cd8a323f57f11a`.
5. Deploy `firestore.rules` only after assigning each user an authorized role in `companies/bredi/users/{uid}`. Do not use the demonstration UI for live financial or stock transactions.

## Business configuration

The initial dashboard reflects the supplied profile: mechanical mustard-seed extraction only, 100 MT/day design capacity, 10 machines, two 12-hour shifts, five seed godowns, one Khali godown, and seven 25,000-litre oil tanks. KG is the canonical mass unit. Registered office and factory address are separate settings. DOC is trading stock only, not a production output.

## Scope and production readiness

This commit establishes the Flutter application shell, responsive navigation, factory dashboard, module entry points, Firebase package setup, and restrictive Firestore rules. Module entry points are currently UI placeholders; purchase, production posting, inventory ledger, billing/PDF, payroll, backups, offline conflict handling, and authorized e-invoice/e-way-bill integrations still require implementation and testing. Firebase credentials/configuration are intentionally not fabricated. Government IRNs are never generated by this application.

Before production deployment, implement server-side validation for all financial and stock postings, immutable append-only audit events, role provisioning, tested offline synchronization/conflict resolution, automated backups, and applicable GST/security reviews. The Firestore rules deny access unless an authenticated user's company membership document exists and grants an allowed role.
